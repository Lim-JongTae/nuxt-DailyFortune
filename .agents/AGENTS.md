# Project Rules (Daily-Fortune)

- **Git 명령어 규칙**: 코드 수정 후 `git add`, `git commit`, `git push` 등 모든 Git 명령어는 에이전트가 자동 실행하지 않으며, 사용자가 직접 검토 후 수행합니다.

- **분석 및 코드 수정 절차 규칙**:
  1. **원인 분석 & 진행 상황 안내**: 요청 수신 시 코드를 즉시 변경하지 않고 문제 원인을 먼저 분석하며, 중간중간 진행 상황을 사용자에게 설명합니다.
  2. **의도 파악 & 수정 방향 제시**: 문제점 전체 내용과 사용자의 의도를 종합적으로 분석하여 구체적인 수정 방향 및 대처 방안을 정리해 제시합니다.
  3. **사용자 승인 후 코드 수정 실행**: 수정할 내용과 대상 코드를 명시한 뒤 사용자의 진행 승인을 대기하며, 사용자가 'OK' 또는 진행 지시어를 주었을 때만 실제 코드 수정 및 실행 작업을 수행합니다.

- **동적 데이터 처리 및 하드코딩 금지 규칙**:
  - 운세 분석 결과, 점수, 텍스트 등 동적 데이터 영역에 오해를 부르는 가짜 하드코딩 고정값(문구/숫자)을 fallback으로 배치하지 않는다.
  - 백엔드/AI 데이터가 없거나 조회가 불가능한 예외 상황 시, 가짜 데이터를 노출하는 대신 "운세 분석 자료를 불러오는 중입니다. 잠시 후 다시 조회해 주세요."와 같은 명확하고 정직한 안내 문구로 대체하거나 100% 실제 데이터 기반으로만 노출한다.

- **Tailwind CSS 클래스 작성 및 Linter 충돌 방지 규칙**:
  - 단일 `class` 문자열 내에서 라이트 모드 유틸리티 클래스와 `dark:` 다크 모드 수식어 클래스가 동일 CSS 속성(`background-color`, `color`, `border-color` 등)을 다루어 IDE/Linter에서 충돌 오진 경고가 발생하는 경우, Vue 동적 `:class="[...]"` 배열 형태로 일반 클래스와 `dark:` 클래스를 분리하여 작성한다.
  - `<UIcon>` 등 자식 컴포넌트 요소는 부모 요소의 텍스트 색상(`currentColor`)을 자동으로 상속받으므로, 부모와 동일한 중복 텍스트 색상 클래스(`text-*`, `dark:text-*`) 작성을 지양하고 상속을 활용한다.
